# Option G - Checkpoint / Regroup

Use `G` when enough state change has accumulated to justify a real reassessment.

## Required Contents

- progress assessment,
- unresolved questions or missing information,
- quality assessment,
- active route status,
- what would falsify or retire the current route,
- what would reopen dormant routes,
- moderator strategic choice,
- next strategic options.

## Strategic Choice Rule

`G` is not a menu for the user.

The Moderator must make and state a strategic choice, such as:
- continue the current route,
- pivot or reframe,
- or finalize.

If user input is genuinely needed, the Moderator should explain:
- what choice they are making provisionally,
- why user input is still required,
- and what specifically is blocked.

Do not offload the strategic decision onto the user when the swarm already has enough information to choose the next move itself.

If unresolved questions still materially affect the architecture, recommendation, or design shape:
- either defer them explicitly and say why deferral is acceptable,
- or keep the swarm in motion with another resolving iteration before `H`.

## Quality Bar

A checkpoint should add one of:
- new evidence,
- stricter route ranking,
- a clarified stop rule,
- or a justified phase transition.

A strong checkpoint also changes the process state:
- it commits to a route decision,
- narrows the next action space,
- or justifies finalization.

A strong checkpoint does not let architecture-shaping unresolveds disappear into a vague "good enough" conclusion.

## Failure Modes

- using `G` as decorative padding,
- summarizing without changing route state,
- asking the user to choose among routes the Moderator should already be able to evaluate,
- replacing strategic judgment with a multiple-choice handoff,
- treating materially consequential unresolved questions as harmless detail,
- claiming resolution when only better questions were produced.
